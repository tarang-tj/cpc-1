# Problem Analysis Report: Counterfactual Precedent Constraint (CPC-1)

## 1. Problem definition and input inventory

### Product/research question

Tool-using agents often make an unsafe analogy: they retrieve a precedent that looks relevant, copy its action, and miss one decisive condition that made a near-identical prior case fail. Standard retrieval augments an answer, but does not require the agent to establish the decision boundary before acting.

CPC-1 is a **runtime decision constraint**, not a claim to have invented counterfactual explanation or contrastive retrieval. Before executing a consequential action, the agent must retrieve:

1. a positive precedent for the proposed action;
2. a semantically close negative precedent in which that action was rejected or caused a failure; and
3. evidence that the current case satisfies the critical predicates distinguishing the two.

If the evidence is missing or contradictory, the agent must request information or abstain rather than act.

### Scope of the first benchmark

The initial, objectively scored domain is operational data work. It has structured inputs, auditable actions, and deterministic or expert-adjudicated ground truth:

| Subproblem | Agent action space | Unsafe analogue failure |
|---|---|---|
| Q1: Entity resolution | merge / do not merge / request identifier | merging two different people or businesses |
| Q2: Data normalization | apply transform / do not apply / request source | converting a value with the wrong unit, locale, date format, or currency |
| Q3: Metric mapping | map metric / do not map / request definition | matching a metric to the wrong denominator, period, or population |

### Attachments and data

No project attachment or input dataset was supplied. This report therefore defines a data contract; it does **not** invent empirical results. The future benchmark must use openly licensed source data or a fully documented synthetic generator. Each record must preserve provenance and a gold decision.

Required case schema:

| Field | Type | Meaning |
|---|---|---|
| case_id | string | immutable identifier |
| task_type | categorical | entity_resolution, normalization, or metric_mapping |
| context | structured JSON plus text rendering | facts visible to the agent |
| candidate_action | categorical | proposed tool action |
| gold_decision | categorical | act, ask, or reject |
| gold_outcome | categorical | safe, unsafe, or insufficient_evidence |
| negative_type | categorical | unsafe_boundary or evidence_boundary for non-safe precedents |
| critical_predicates | list | facts that decide the action |
| provenance | URI/hash | source or generator version |
| near_miss_group | string | paired or clustered cases differing on decisive facts |

## 2. Decision target, constraints, and assumptions

### Required outputs

For every input case, the agent must return a structured decision:

\[
d(x) \in \{\text{ACT}(a),\ \text{ASK}(q),\ \text{REJECT}(\ell)\}
\]

with a machine-verifiable certificate containing the positive precedent, negative precedent, critical predicates, evidence status, and decision.

### Hard constraints

1. The same retrieval corpus, embedding index, candidate-pool size, and agent-context budget must be used by CPC-1 and all baselines.
2. A CPC-1 action is valid only when its certificate passes deterministic validation.
3. The negative precedent must share the candidate action and be sufficiently similar to the current case, while having an opposing outcome.
4. The evaluation split must prevent leakage by grouping all members of a near_miss_group into one split.
5. Free-form model reasoning cannot be accepted as evidence; every critical predicate must resolve to a source field, an explicit unknown, or a contradiction.
6. No system may claim safety improvement without reporting the cost in correct actions, unnecessary abstentions, latency, and retrieval failures.
7. The first registered comparison uses Qwen/Qwen2.5-7B-Instruct, temperature 0, seed 2027, and a 256-token completion limit. It retrieves exactly \(h=8\) action-matched candidates with intfloat/e5-base-v2 and a FAISS HNSW index (M=32, efSearch=128); all systems receive at most 1,600 tokens of identically rendered precedent evidence. The implementation must record the exact model and corpus revision hashes before the held-out split is unsealed.

### Assumptions and their verification

| Assumption | Why needed | Check before experiment |
|---|---|---|
| Structured fields capture the decisive distinctions | enables deterministic certificate validation | sample 100 cases and adjudicate field sufficiency |
| Positive and negative near-miss precedents can be mined | enables contrastive retrieval | report pair coverage by task and class |
| Gold labels are reliable enough to score unsafe actions | gives the benchmark meaning | dual annotation or deterministic generator tests |
| Ask/abstain is an available operational action | prevents forced unsafe actions | include explicit gold labels for insufficient evidence |
| Embedding similarity can identify superficially similar cases | supports retrieval candidate generation | audit similarity distribution of valid and invalid pairs |

## 3. Formal model

### 3.1 Notation

Let the case archive be

\[
\mathcal{D}=\{(x_i,a_i,y_i,E_i,g_i)\}_{i=1}^n,
\]

where \(x_i\) is the observed context, \(a_i\) is an action, \(y_i\in\{\text{safe},\text{unsafe},\text{insufficient\_evidence}\}\) is the adjudicated outcome, \(E_i\) is provenance-backed evidence, and \(g_i\) is the near-miss group. \(\pi\) is the frozen base policy that proposes the candidate action \(a=\pi(x)\).

For a new case \(x\), the base agent proposes \(a=\pi(x)\). The retriever produces a positive precedent \(p^+\) and negative precedent \(p^-\):

\[
p^+\in\{p\in\mathcal{D}:a_p=a,\ y_p=\text{safe}\},\qquad
p^-\in\{p\in\mathcal{D}:a_p=a,\ y_p\in\{\text{unsafe},\text{insufficient\_evidence}\}\}.
\]

Let \(s(x,p)\in[0,1]\) be an embedding similarity and \(\Delta(p^+,p^-)\) be the field-level predicate differences. A mined negative precedent is admissible only if:

\[
s(x,p^- )\ge \tau_{near},\qquad
|\Delta(p^+,p^-)|\le k,\qquad
\text{outcome}(p^+)\ne\text{outcome}(p^-).
\]

The small difference set prevents the system from using an irrelevant negative example. \(k\) and \(\tau_{near}\) are tuned solely on the development split. A negative record is tagged \(\nu(p^-)\in\{\text{unsafe\_boundary},\text{evidence\_boundary}\}\): the former demonstrates that acting is wrong under a conflicting observed value; the latter demonstrates that action is blocked because an indispensable fact is absent. These types are never treated as interchangeable.

### 3.2 Minimal distinguishing predicate set

Let \(B(x,p^+,p^-)=\{b_1,\ldots,b_m\}\) be the candidate safe-value literals that distinguish the precedents. A literal is \(b=(f_j,z_j^+)\), meaning that normalized field \(f_j\) must equal the safe precedent's value \(z_j^+\). Candidate literals are generated deterministically from fields whose normalized values differ between \(p^+\) and \(p^-\). Each literal has a status under current evidence:

\[
\operatorname{sat}(x,b_j)\in\{\text{matched},\text{mismatched},\text{unknown},\text{contradicted}\}.
\]

Let \(\mathcal{N}_h(x,a)\) be the \(h=8\) highest-similarity, action-matched archive records satisfying \(s(x,p)\ge\tau_{near}\), excluding the current near-miss group. For a subset \(S\subseteq B\), write \(z_S^+\) for the safe values of its literals and define the empirical local support \(n_+(S)=\#\{p\in\mathcal N_h:y_p=\text{safe},\ p_S=z_S^+\}\) and \(n_-(S)=\#\{p\in\mathcal N_h:y_p\ne\text{safe},\ p_S\ne z_S^+\}\). Its separation score is

\[
C(S)=\frac{n_+(S)}{\#\{p\in\mathcal N_h:p_S=z_S^+\}}-\frac{\#\{p\in\mathcal N_h:y_p=\text{safe},\ p_S\ne z_S^+\}}{\#\{p\in\mathcal N_h:p_S\ne z_S^+\}},
\]

with any zero denominator treated as ineligible. The critical subset \(B^*\subseteq B\) is the smallest set with adequate support and separation:

\[
B^*=\arg\min_{S\subseteq B}|S|
\quad \text{s.t.}\quad n_+(S)\ge\eta,\ n_-(S)\ge\eta,\ C(S)\ge\delta.
\]

For CPC-1, \(\eta=1\) because \(\mathcal N_h\) is deliberately small; \(\delta\) and \(k\) are selected on development data and frozen before test evaluation. Ties are resolved by greater \(C(S)\), then greater \(n_+(S)+n_-(S)\), then lexicographic field order. If no eligible \(S\) exists, \(B^*=\varnothing\) and the action gate fails. The first version uses these deterministic field-difference and counting rules, not a local decision tree. An LLM may propose normalized field values, but schema validation must either accept or reject them; it does not determine \(B^*\) by prose alone.

### 3.3 Counterfactual Precedent Constraint

The gate \(G\) permits an action only if the certificate has positive support, an admissible negative precedent, and resolved critical evidence:

\[
G(x,a)=
\mathbb{1}[p^+\ \text{exists}]\cdot
\mathbb{1}[p^-\ \text{exists}\ \land\ \nu(p^-)=\text{unsafe\_boundary}]\cdot
\mathbb{1}[B^*\ne\varnothing]\cdot
\prod_{b\in B^*}\mathbb{1}[\operatorname{sat}(x,b)=\text{matched}]\cdot
\mathbb{1}[\neg\text{contraindication}(x,a)].
\]

The policy is:

\[
d_{CPC}(x)=
\begin{cases}
\text{ACT}(a), & G(x,a)=1,\\
\text{ASK}(q^*), & \exists b\in B^*:\operatorname{sat}(x,b)=\text{unknown}\ \text{or an evidence-boundary precedent identifies an unresolved indispensable literal},\\
\text{REJECT}(\ell), & \exists b\in B^*:\operatorname{sat}(x,b)\in\{\text{mismatched},\text{contradicted}\}\ \text{or no actionable evidence-boundary query and no admissible unsafe-boundary pair exists}.
\end{cases}
\]

\(q^*\) requests the unresolved literal with the largest \(C(\{b\})\); ties use lexical field order. An evidence-boundary precedent may nominate a missing field for \(q^*\), but it can never validate \(\text{ACT}(a)\). \(\ell\) is a deterministic reason code: no_pair, no_boundary, mismatched_literal, contradictory_evidence, or contraindication. The certificate stores each literal's field, required safe value, observed value, provenance, and status. This is a local risk-separation heuristic, not an unverified causal claim.

### 3.4 Objective and tradeoff

The evaluation does not optimize raw accuracy alone. Let \(U\) be unsafe acts, \(A\) unnecessary abstentions/rejections, \(Q\) unnecessary questions, and \(T\) end-to-end decision time:

\[
\mathcal{L}=c_U U+c_A A+c_Q Q+c_T T, \qquad c_U>c_A>c_Q\ge0.
\]

Costs are reported as sensitivity curves rather than a single arbitrary setting. The primary empirical comparison is CPC-1 versus a same-budget top-\(k\) semantic retrieval baseline that supplies precedents but imposes no counterexample gate.

## 4. Algorithms and implementation contract

### Offline benchmark construction

1. Ingest source records and canonicalize fields while retaining raw values and provenance.
2. Produce gold action/outcome labels and mark decisive fields.
3. Mine positive-negative pairs sharing an action and a near-miss relationship.
4. Split by near_miss_group, then freeze train/development/test manifests.
5. Publish a validator that checks every CPC certificate without an LLM judge.

### Runtime CPC-1 algorithm

1. Parse a candidate case into the approved schema.
2. Obtain the base action proposal \(a\).
3. Retrieve action-matched positive and negative candidates with the same index and budget as the baseline.
4. Select the admissible contrastive pair maximizing similarity subject to the near-miss constraints.
5. Compute \(B^*\), resolve each predicate against current evidence, and validate the certificate.
6. Act only if the gate passes; otherwise ask for the highest-value missing fact or reject.
7. Log the decision, certificate, latency, and validator result.

### Complexity

With an approximate nearest-neighbor index, retrieval is approximately \(O(\log n)\) per action partition. Predicate comparison is \(O(f)\) for \(f\) normalized fields; selection among \(h=8\) retrieved candidates is \(O(h^2f)\). The fixed cap keeps pair-selection cost auditable.

## 5. Evaluation design and falsifiability

### Baselines

1. **Semantic-RAG baseline:** same base model, corpus, action space, and retrieval budget; receives top-\(k\) precedents and decides without the CPC gate.
2. **CPC-1 ablation:** retrieve a positive precedent and use the evidence gate but remove the negative-precedent requirement. This isolates whether the contrastive requirement, rather than extra retrieval structure, is responsible.

These are comparison conditions, not additional modeled solutions.

### Primary metrics

| Metric | Definition | Desired direction |
|---|---|---|
| Unsafe Action Rate (UAR) | unsafe autonomous actions / all held-out decision cases | lower |
| Correct Action Rate (CAR) | correct autonomous actions / clear-action held-out cases | higher |
| Unnecessary Abstention Rate (UAbR) | abstentions or rejections on clear-action cases | lower |
| Question Precision | useful questions / all questions | higher |
| Pair Coverage | cases with valid \(p^+,p^-\) / all cases | higher |
| Certificate Faithfulness | valid certificates aligned with gold decisive fields / issued certificates | higher |
| Median latency | wall-clock decision time | lower |

### Pre-specified acceptance test

On the held-out **hard near-miss** test set, CPC-1 is promising only if all of the following hold against Semantic-RAG:

1. UAR falls by at least 25% relatively and a stratified bootstrap 95% confidence interval for the reduction excludes zero.
2. CAR on clear cases decreases by no more than 10 percentage points.
3. UAbR increases by no more than 15 percentage points.
4. At least 90% of CPC-issued certificates pass deterministic schema and provenance validation.

These are project acceptance criteria, not established industry thresholds. If any criterion fails, the honest result is that CPC-1 did not demonstrate a useful improvement under this setup.

### Stress tests

| Test | Purpose |
|---|---|
| Decisive-field swap | change one critical field while retaining superficial similarity |
| Retrieval poisoning | inject high-similarity but mislabeled or irrelevant precedent records |
| Missing-evidence masking | remove exactly one required predicate value |
| Paraphrase/format perturbation | change wording or input serialization without changing facts |
| Cross-task transfer | hold out one operational task type to test whether the gate overfits a schema |

## 6. Risks, limitations, and fallbacks

| Risk | Consequence | Mitigation / fallback |
|---|---|---|
| Pair coverage is low | CPC rejects too often | report coverage; use CPC only for covered actions and route uncovered cases to human review |
| Critical fields are incomplete | false confidence in certificates | human audit; classify as insufficient evidence rather than act |
| Embedding similarity hides semantic differences | poor near-miss mining | enforce structured field constraints and audit mined pairs |
| Synthetic benchmark is too tidy | no real-world relevance | add a second sourced dataset after initial protocol validation |
| Latency becomes impractical | operational cost | cache pair candidates; measure latency separately, never hide it |
| Existing work overlaps | novelty claim is overstated | claim only the specific action-time pair-and-predicate constraint and its benchmark, never “first counterfactual agent system” |

## 7. Literature basis and novelty boundary

Contrastive and counterfactual explanations are established XAI topics; CPC-1 does not claim to create them. Stepin et al. survey those methods. Existing work also uses positive/negative examples during *optimization* of tool agents, e.g., AvaTaR. CPC-1 differs in the testable claim that **each consequential runtime action must be blocked unless a retrieved negative near-miss and its minimal distinguishing evidence have been checked by a deterministic certificate validator**.

This distinction still requires a full literature review before publication. It is a project hypothesis, not a priority claim.

1. Daniel Stepin, Jose M. Alonso, Alejandro Catala, and Martin Pereira-Fariña. “A Survey of Contrastive and Counterfactual Explanation Generation Methods for Explainable AI.” *IEEE Access* (2021). DOI: https://doi.org/10.1109/ACCESS.2021.3051315
2. Xinru Wang and Ming Yin. “Are Explanations Helpful? A Comparative Study of the Effects of Explanations in AI-Assisted Decision-Making.” *IUI 2021*. DOI: https://doi.org/10.1145/3397481.3450650
